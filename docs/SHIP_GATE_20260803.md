# Ship Gate — 2026-08-03

Evidence for the COMPLETE & SHIP pass. Branch `complete/ship-gate`, PR #313.

The bar was: a stranger clones tomorrow, follows the README, and every
advertised path works first try. This records what was found, what was fixed,
what is deliberately not built, and what is blocked.

## 1. What the audit found, and what happened to it

`scripts/audit_stubs.py` reported **41** hollow functions. First run reported
552 — it was walking eight stale local git worktrees and counting every stub
nine times, and on Windows `os.path.relpath` yields `tests\foo.py` so the
spec's `rel.startswith("tests/")` never matched and every test helper was
reported as a shipped stub. Both deviations are documented in the script.

| bucket | count | disposition |
|---|---|---|
| implemented for real | 3 | the drawing ingest path — F6 |
| deleted as dead code | 3 | `get_rag_filters`, `_legacy_sync_generate_unused`, `_blocks_to_tables` |
| roadmap | 16 | registered in docs/KNOWN_INCOMPLETE.md with the data source each needs |
| correct by design | 10 | Protocol bodies, sklearn `get_params`, format-map `__missing__` |
| test harness | 10 | fakes inside `scripts/audit_voice_block.py` |

`audit_stubs.py` now exits 0.

### The three that mattered

`_process_drawing_page` builds every drawing result from five helpers, and
three were hollow. Every drawing that went through the container came out
with `tables: []`, `annotations: []`, `title_block: {}` — and nothing said
so. A drawing keeps its numbers in its schedules, so this was the ingest path
dropping the most retrievable content on the sheet while reporting success.

### The one nobody would have found by reading

`pdf_parser._blocks_to_tables` returned `[]` under the comment *"real table
extraction handled by pdfplumber"*. It was not. `parse()` tries
`_parse_with_pymupdf` **first** and it succeeds for essentially every PDF, so
the pdfplumber branch never ran. Every specification, BOQ and schedule came
out of the document engine with `tables == []`, and the comment made that look
deliberate.

### Findings A and C were both dead code

Finding A (`containers/base.py::get_rag_filters`) was flagged as a possible
silent isolation break. It had exactly **one** reference in the repository:
its own definition. No caller, no override. It could not leak anything
because nothing ever asked it. Deleted rather than made abstract — forcing
every container to implement an uncalled method is churn, not safety.

Isolation is really enforced one layer down, by `WHERE project_id = ...` on
every read path in the vector store. That is what F4 pins.

## 4. Secrets — two live credentials were in the tree

`scripts/scan_secrets.py` found and this branch removes:

- a live Fork API key, written out twice in `docs/recovery/re_import_runbook.md`
- a live Render API key hardcoded in `scripts/windows/fork-tunnel-update.ps1`,
  which put a working credential in every clone. It now reads
  `$env:RENDER_API_KEY` and exits with a clear message if unset.

The **first** version of the scanner walked straight past two more, written as
`TOK=rnd_...` — no quotes, and a variable name no secret-name pattern matches.
That near-miss is why there is a provider-prefix rule needing neither a name
nor quotes, and why quotes are now optional. Both shapes are pinned in tests.

27 tests, including a false-positive suite: `os.getenv` calls, placeholders,
`requirements.txt` sha256 hashes and lockfile integrity strings must not fire.
A scanner with false positives gets ignored, which is worse than none.

## 5. A CI gate that had never measured anything

`.github/workflows/test.yml` promoted "Diff coverage" to blocking, but no step
ever installed `diff-cover`. It had been failing with `command not found` on
every pull request since — exit 127, no report, no output, reading exactly
like a coverage failure. `main` stayed green because the step is
`if: github.event_name == 'pull_request'`.

Fixed, and the summary now prints even when the gate fails — previously a
non-zero exit killed the step before the report was shown, so a failing gate
said nothing about which lines were uncovered.

Two new blocking gates added (`integrity` job): `audit_stubs.py` and
`scan_secrets.py`. Both are seconds-cheap and both have already caught
something real, which is the bar for blocking rather than reporting.

## 6. README — a stranger could not have got the UI

Found by following it as a stranger rather than reading it as its author:

1. `git clone git@github.com:...` — SSH. Anyone without a key on the repo
   fails at step one. Now HTTPS.
2. **The chat UI never appears.** `frontend/dist` is a build artifact and is
   not committed; `app/main.py` mounts it only `if os.path.isdir(...)`. The
   Quickstart never mentioned `npm ci && npm run build`, so following it
   exactly gives the API and `/docs` and no chat surface.
3. `npm run dev` undocumented, and there is no vite proxy — the app calls
   `VITE_API_BASE`, defaulting to `localhost:8000`.

Also verified against the code and now stated: `requirements.txt` alone is
sufficient (the default embedder `model2vec` is a base dependency; the
`-rag`/`-ml`/`-cv` extras are large and optional), and no database setup is
needed because `get_database_url()` falls back to SQLite under `DATA_DIR`.

## 7. Stated limitations

**~~Extracted drawing tables do not become retrieval chunks.~~ NOW CLOSED** —
see §10.

**A drawing is only recognised by its filename.** `_looks_like_drawing`
matches `dwg`/`drawing` in a PDF's filename. A drawing named `Sheet 4 of
12.pdf` is missed. Deliberate, and the same trade `_looks_like_boq` makes for
the same reason: running table detection over every page of every PDF would
add real cost to a bulk re-index, and re-encode runs on this corpus already
sit near a capacity wall.

**Title-block values on the line below their label are missed.** Every
separator is `[ \t]*`, never `\s*`, so a value is read only from its label's
line. Deliberate: crossing the newline makes an empty `DRAWN BY:` capture the
following `CHECKED BY` label as the drafter's name. Missing a field is
recoverable; inventing one on a client drawing is not.

## 8. Skips, xfail, xpass

116 skips in the virgin CI profile, all environment- or profile-conditional,
none hiding a failure: optional native dependencies (`ifcopenshell`, `ezdxf`,
PyMuPDF), Node/tsc absent on the runner, no `REDIS_URL`, no Postgres
`DATABASE_URL`, POSIX-only resource limits, Windows symlink privileges, live
provider acceptance tests needing a real key, and the CI profile flags
(`CEREBRUM_VIRGIN`, `CEREBRUM_DOMAIN_KITS`, `HATS_ENABLED`).

### A skip I added and then removed

Four `test_bim_extractor` tests failed once on this Windows box with
`ifcopenshell not installed`, and I added a platform guard for them,
documenting it as "the wheel does not ship a build for Windows/py3.11".

**That was wrong and the guard is reverted.** `import ifcopenshell` succeeds
here (0.8.5) and all ten tests in the file pass, three runs in a row,
including under random ordering. The original failure was transient and its
cause is unknown; what is certain is that it was not a missing platform
build. `ifcopenshell.geom` — a different, genuinely unavailable submodule
guarded by an `importorskip` in `test_w3_planted_truth_drawings.py` — is what
the "not built for windows/64bit/python3.11" warning in the log refers to,
and I read that as applying to the whole package.

The file is byte-identical to its pre-change state. A skip added for a flake
is the exact test-weakening the brief forbids, and it would have silently
removed the only coverage of IFC parsing on any host where the flake recurred.

## 9. BLOCKED — and how the compose item stopped being blocked

`compose up` health was filed as BLOCKED: no container runtime exists on the
maintainer's Windows machine (docker, podman and nerdctl all absent; WSL
reports "Class not registered"), so it had never been executed **anywhere,
by anyone**.

Moving the verification to the Linux CI runner resolves it on the same
artifact rather than a proxy. The `compose-health` job in
`docker-publish.yml` runs `docker compose up -d --build --wait` from a clean
checkout — `--wait` blocks until every service with a healthcheck reports
healthy and fails if a container exits first, and both services define one —
then asserts `GET /health` returns 200.

Running from a *clean checkout* is the point, and it paid for itself
immediately: compose bind-mounted `./.env`, which is gitignored, so on a
fresh clone Docker created a **directory** at that path and the app tried to
read a directory as a file. Now `env_file` with `required: false`, which
reads it when present and is a no-op when it is not.

`docker build` was already proven by run `30823469977` on the merged tree.
(Not "every push" — one earlier run, `30823321263`, was *cancelled* by a
subsequent push and proves nothing.)

Operator-only items, unchanged: the Fernet key needs an off-machine copy in a
password manager, `HF_TOKEN` needs setting for CI and Render, and the
`ab-2023-101` corpus backfill is an owner action.

## 10. Drawing schedules now reach retrieval

The §7 limitation, closed. `doc_index::_drawing_chunks_for_document`
serialises recovered schedules and the title block into chunks and appends
them on **both** ingest paths (`index_project` and `index_document`),
patterned on `_boq_chunks_for_document`. Wiring only one path would have
reproduced the exact bug class this whole gate kept finding: correct in the
test, absent in the path production uses.

A scanned sheet — named as a drawing, no text layer — emits a
`SCHEDULE-VALUE GUARD` chunk telling the model not to state bar marks,
diameters or quantities from it. Same role as `_boq_no_total_guard`: without
it, chat sees a drawing in the corpus, finds no schedule, and is free to
invent a plausible bar diameter.

**The part worth remembering is how the test went wrong first.** Version one
asserted that `B1` and `48` were retrievable after ingest. It passed with the
wiring **disabled** — PyMuPDF's raw text layer already contains both, as
loose words. It proved nothing.

The loose value was never the problem. The problem was that nothing tied it
to anything: `48` sat in the corpus with no indication it is the QUANTITY,
for bar mark B1, of 16mm diameter, on this sheet. So the test now asserts on
the ROW as a unit — `B1 | 16 | 48` — which only the structured chunk can
produce, and on the schedule's classification. Verified by disabling the
wiring and confirming both tests fail.

17 tests in `tests/e2e/test_f7_drawing_schedule_retrieval.py`, including the
filename gate checked against real drawing and non-drawing filenames taken
from the indexed corpus.
